# Raw Data Hub sync request authentication

**Status: deployed and live-verified, 2026-10-17.** The protected raw sync Edge Function is version 10 with bundle SHA256 `6ec4a93906c4cc7afe6767239b1af6773f454eca7f2ac99475773b435e7b7ed9`. Gateway JWT verification remains enabled.

`raw-datahub-sync` can append rows to the operational Data Hub Sheet and update sync state. Supabase Edge `verify_jwt=true` is not sufficient for the scheduled caller: a publishable key passes gateway JWT validation. The handler therefore checks the existing `x-myc-invoke-token` through `ops.verify_shadow_import_token` before parsing the request body, reading Google Sheets, or entering any sync mode. Missing, invalid, or unverifiable tokens receive a no-store `403 FORBIDDEN` response. The service-role key remains server-side and is used only for the verifier RPC and existing backend operations.

The auth-only SQL is [MYC_RAW_SYNC_AUTH_REVIEW.sql](sql/MYC_RAW_SYNC_AUTH_REVIEW.sql), copied to [the formal migration](../../supabase/migrations/20261017025022_myc_raw_sync_auth.sql). The update retained Cron #5's existing active five-minute schedule and inserted the `x-myc-invoke-token` header through a server-side Vault lookup. It verifies the job identity, exact project/function URL, and original request shape, and uses named `job_id` and `command` arguments only. It asserts that job name, schedule, database, execution user, active state, and full command remain as expected. Cron #11 remains inactive.

This reuses `myc_shadow_import_invoke_token`; it does not create or reveal a secret. The shared token will authorize both the existing shadow-import route and the raw-sync route, so its custody has cross-route impact. Edge gateway JWT verification remains enabled as a second gate. Do not put the token in source, logs, responses, Sheets, or client code.
